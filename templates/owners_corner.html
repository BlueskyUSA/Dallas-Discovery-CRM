Protecting the Hub's code

Whoever can change the code in GitHub can change the live Hub and reach the database. These steps keep that list short. Menu names in GitHub, Render and Brevo change now and then, so follow the closest match.

1. Two-step login (everyone with access)

  • GitHub: your picture (top right) → Settings → Password and authentication → Two-factor authentication → Enable.
  • Render: Account Settings → Security → turn on two-factor authentication.
  • Brevo: your name (top right) → Profile → Security → turn on two-factor authentication.

2. Require approval before a change goes live (GitHub)

  1. Open the HUB_CRM repository → Settings → Branches → Add branch ruleset (or Add rule).
  2. Branch name pattern: master.
  3. Tick Require a pull request before merging and require 1 approval.
  4. Leave "Do not allow bypassing" / "Include administrators" unticked, so your own usual uploads still work. Everyone else must go through you.

3. Adding a technical maintainer (only when someone truly takes that role)

  1. GitHub: HUB_CRM → Settings → Collaborators → Add people → choose the role Write (never Admin).
  2. Render: Account Settings → Team members → Invite → choose the lowest role that still lets them view logs and deploys.
  3. Write their name and role under "People who help" on the Hub Ownership page.

4. When the LLC exists

  • Move the GitHub repository and the Render service into the LLC's accounts (GitHub: Settings → Transfer ownership), using an email that belongs to the LLC.
  • Update the Software accounts list under Administrator → Software & go-live.

Max and Pamela as Administrators do not need GitHub or Render access to run the Hub day to day. Give it only if they will also maintain the software.
