Administrators (backup operators) ▾

An Administrator can do everything the Owner can in the Hub: switches, letters, logins, Site Access and the Accounting & Legal logins. Two things stay with the Owner: making or removing Owners and Administrators, and changing the Owner's own login.

To add one: Contacts → find the person → Hub Login → Administrator → Set. They are emailed a login link. They also need their own access to Render, GitHub and Brevo to cover everything outside the Hub; that is set up in those services, not here.

How to change a switch in Render ▾
  1. Log in to Render and open the Hub service (dallas-discovery-crm).
  2. Click Environment in the left menu.
  3. Click Add Environment Variable (or edit the existing one).
  4. Type the switch name exactly as shown above, for example SESSION_LETTERS_LIVE, and set the value to 1. To turn it back off, set it to 0 or delete it.
  5. Click Save. Render restarts the Hub by itself (about a minute). Then hard-refresh this page: the switch shows ON.

Order that makes sense: SESSION_LETTERS_LIVE first, then AUTO_LETTERS_LIVE (it needs the first one), then BLASTS_LIVE when you are ready to send email blasts.

Error alerts ▾

If the Hub hits an unexpected error, it emails the Owner (what page, what error, where in the code). The same problem is emailed at most once every 30 minutes, and never more than 10 alert emails an hour. Visitors just see a short apology page. No names, passwords or form contents are in the email.

To send alerts to a different address, add ERROR_ALERT_EMAIL in Render's Environment. Several addresses can be separated by commas.

One thing the Hub cannot do: if the whole site is down, it cannot email you about itself. For that, turn on Render's own failure emails (Render → your account → Notification settings) and a free outside checker such as UptimeRobot watching the Hub's web address.

Uploading an update to GitHub ▾
  1. Unzip the Update file and open the unzipped folder.
  2. Drag the templates folder and the loose .py files onto GitHub: Add file → Upload files.
  3. Commit once (one commit for everything).
  4. Wait for Render to show Live, then hard-refresh the Hub.

Each file replaces the earlier copy of the same name. If Render shows a failed deploy, open the deploy log and send it to Claude.

Using Render's Shell for a command ▾
  1. In Render, open the Hub service and click Shell.
  2. Paste the whole command Claude gives you, including the python3 at the start, and press Return.
